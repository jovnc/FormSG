Product domains

Data flows

These diagrams show how high-risk product flows cross frontend, backend, shared packages, persistence, and integrations.

Encrypted storage submission

Respondent browser
  -> loads public form metadata
  -> validates and submits answers
Backend public form routes
  -> validates form state, captcha/auth, fields, attachments, payment rules
  -> persists encrypted submission metadata/payload
  -> emits webhook if configured
Admin browser
  -> loads encrypted responses
  -> captures secret key through useSecretKey
  -> Comlink decryption worker uses @opengovsg/formsg-sdk crypto
  -> renders table/detail/export

Multirespondent workflow (MRF)

Admin defines workflow steps
  -> shared workflow types and Form model persist assignments
Respondent step 1 submits
  -> backend creates submission with workflow state
  -> next respondent receives link/notification
Respondent step N opens link
  -> frontend extracts previous values
  -> augmentFieldWithMrfWorkflowDisabling locks earlier fields
  -> backend validates allowed step changes
Final step
  -> final submission state is available to admins and webhooks

Email-mode submission

Respondent submits email-mode form
  -> public-form submission route validates payload
  -> email submission service renders response email
  -> services/mail sends through SES/Maildev
  -> bounce notifications update bounce state
  -> admin sees delivery-related state and feedback through form modules

Payment flow

Public form submit
  -> create pending submission/payment record
  -> redirect or initialize Stripe payment
Stripe event
  -> /api/v3/notifications/stripe verifies webhook
  -> payment/submission state updated idempotently
Reconciliation service
  -> scheduled check repairs missed or inconsistent state
  -> cron-protected backend payment route finalizes decisions

Verified fields

Respondent authenticates with trusted provider
  -> backend obtains trusted attributes
  -> verification module signs verified content
  -> public form stores verified values with signature material
  -> SDK/backend verification helpers check integrity before trust
