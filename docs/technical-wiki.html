Overview

FormSG is a government form builder for creating public forms, collecting responses securely, authenticating respondents, and managing submissions, payments, webhooks, and operational reporting.

pnpm monorepo apps/*, packages/*, services/*
Node 22+ engines.node >=22.22, pnpm 10.30.3
React + Express Vite SPA served by an Express API in production
MongoDB Mongoose models with encrypted storage-mode submissions

Primary apps

apps/frontend is the React admin/respondent SPA. apps/backend is the Express API, session host, SPA server, and integration gateway.

Shared contract layer

packages/shared defines domain types, constants, validators, feature flag keys, logic helpers, and response-mode projections.

Independent services

Lambda-style services handle GuardDuty virus scanning, PDF generation, and Stripe payment reconciliation outside the main API process.

How to use this wiki: start with the architecture and runtime sections, then jump to the app or domain area you are changing. The extension guides list the files that usually change together for common workstreams.

Architecture

FormSG follows a contract-first monorepo architecture. Shared domain contracts are consumed by the frontend, backend, SDK, and supporting services, while integration adapters stay close to the backend or their owning service.

React SPA apps/frontend, Vite, Chakra UI, field renderer, admin builder
Express API apps/backend, routes, controllers, services, Mongoose models
Both apps consume shared contracts and SDK functionality
formsg-shared Types, constants, validators, field definitions, logic, payment helpers
FormSG SDK Webhook signatures, submission decryption, verified field signatures
Sidecar services PDF generation, virus scanning, payment reconciliation

Request lifecycle

Bootstrap
Backend starts at apps/backend/src/app/server.ts, loads Datadog, MongoDB, AWS clients, Stripe, and Express.
Middleware
Express applies parsers, sessions, helmet, compression, request IDs, rate limits, logging, static assets, and routes.
Routing
/api/v3 requests enter versioned routers; public APIs use /api/public/v1; frontend fallback serves the SPA.
Domain logic
Controllers delegate to services, services use Mongoose and external adapters, and errors flow through typed mappings.

Frontend lifecycle

HTML shell
apps/frontend/index.html mounts #root and loads the app and Datadog chunk.
Bootstrap
src/index.tsx initializes polyfills, i18n, dayjs, optional MSW, and renders <App />.
Providers
App.tsx wires React Query, Chakra, Auth, GrowthBook, Helmet, and Turnstile providers.
Routes
AppRouter.tsx creates route trees for public forms, admin forms, login, dashboard, billing, and static pages.

Design principles visible in the code

Single domain contract

Field types, form DTOs, payment enums, and validators are centralized in packages/shared.

Feature modules over layers

Frontend and backend group most logic by domain feature, with route/controller/service boundaries on the backend.

Adapter boundary

Stripe, AWS, identity providers, email, SMS, captcha, and analytics are isolated behind backend modules or service packages.

Response mode branching

Email, storage, and multirespondent forms have distinct projections, validation paths, and submission flows.

Build-time plus runtime config

Vite builds the frontend, while the backend injects runtime window.__ENV__ values into the served SPA.

Plain pnpm orchestration

No Turbo or Nx; root scripts coordinate workspace builds, tests, lint, Docker, and sidecar dev services.

Runtime model

Local development runs a Vite frontend, backend container, MongoDB, LocalStack, MailDev, MockPass, Stripe CLI, PDF Lambda emulator, and virus scanner emulator. Production serves compiled frontend assets from the backend.

Domain modules

Forms

modules/form contains shared form services, admin form services, public form services, settings, logic, payments, templates, issues, and AI assistance.

Submissions

modules/submission handles email-mode, encrypted storage-mode, multirespondent workflows, upload receiver middleware, and verified content.

Auth

modules/auth, spcp, sgid, and myinfo support admin sessions and respondent government identity flows.

Payments

modules/payments and payment routes own Stripe Connect, payment records, receipts, proofs, and reconciliation APIs.

Webhooks

modules/webhook signs outbound webhook payloads with the SDK and retries failed deliveries via SQS.

Operations

Analytics, feature flags, billing, bounce handling, feedback, issue reporting, workspace, user, intranet, WOGAA, and Datadog modules.

Database models

Mongoose model factories live in src/app/models. Core collections include forms, submissions, pending submissions, users, agencies, workspaces, payments, OTP/login tokens, feedback, issues, statistics, whitelists, and feature flags. Field sub-schemas under models/field mirror shared field types from formsg-shared/types/field.

Error handling pattern

Validate
Celebrate/Joi rejects malformed requests before controller logic.
Execute
Services often return neverthrow Result/ResultAsync values.
Map
Module-specific mapRouteError utilities convert domain errors into HTTP status and messages.
Handle
Global Express error handlers normalize celebrate, body-parser, Mongo, and unknown errors.

Forms and submissions

Forms are the central domain object. A form can be public or private, can use different respondent auth modes, and can collect responses via email, encrypted storage, or multirespondent workflows.

Email mode

Legacy response flow where submissions are sent by email, with backend validation and mail delivery.

Storage mode

Encrypted submissions stored in MongoDB/S3-backed workflows, decrypted client-side by admins using the SDK.

Multirespondent mode

Workflow-based forms with multiple respondents, step state, status tracker, and v3/v4 answer adapters.

Auth and access

FormSG has separate auth concepts for administrators, respondents, API users, cron jobs, and form collaborators.

Auth type Backend modules Mechanism
Admin session modules/auth, auth.middlewares.ts Email OTP or identity provider login; session stored in MongoDB via connect-mongo.
Admin sgID/SSO/WOG AD modules/auth/sgid, auth/sso, auth/wogad OAuth/OIDC or MSAL-backed admin login flows.
Respondent SingPass/CorpPass modules/spcp, routes/singpass OIDC flows with JWKS endpoints and MyInfo integration.
Respondent sgID modules/sgid sgID callbacks and respondent session/identity checks.
Public API key Public v1 routes, auth middleware Bearer token format with user ID and hash; platform users may impersonate by email.
Cron payment secret Payment reconciliation routes x-formsg-cron-payment-secret header.
Form collaborator permissions admin-form.utils.ts, workspace modules Permission-level assertions before admin form mutations.
Frontend auth note: the frontend stores a local authenticated hint in localStorage, but the real authority is the backend session cookie. Axios 401 handling clears the local hint.

Payments

Payment support is built around Stripe Connect, payment fields in forms, pending submissions, receipts, payment-proof storage, and reconciliation.

Backend

  • modules/payments owns Stripe service code and payment domain services.
  • routes/api/v3/payments exposes payment, webhook, receipt, and reconcile APIs.
  • models/payment.server.model.ts stores payment records.
  • services/form-payment-reconciliation calls reconcile endpoints on a schedule.

Frontend/shared

  • features/admin-form/settings configures payment settings.
  • features/public-form handles payment-enabled respondent flows.
  • formsg-shared/types/payment defines payment enums and DTOs.
  • formsg-shared/utils/payments and paymentProductPrice format and validate amounts.

Extension guides

Common changes touch multiple packages. Use these checklists to avoid updating only one side of a shared contract.

Add a new field type

Shared contract
Add the field type and DTOs under packages/shared/types/field, update BasicField, constants, and validation helpers if needed.
Backend persistence and validation
Add/adjust Mongoose field schema under apps/backend/src/app/models/field and Joi validators under utils/field-validation.
Public renderer
Create apps/frontend/src/templates/Field/<NewField>, export it, and register it in FieldFactory.tsx.
Admin builder
Update builder creation metadata, ordered field constants, and the edit panel under features/admin-form/create.
Tests and docs
Add shared/backend validator tests, frontend field tests/stories, i18n strings, and any response export/decryption updates.

Add a backend endpoint

Route
Add Express route wiring under the correct routes/api/v3 subtree and apply auth/rate-limit/celebrate middleware.
Controller
Keep request/response mapping thin; delegate domain work to a service.
Service
Use existing model factories, shared validators/types, and Result/ResultAsync patterns where the module already uses them.
Error mapping
Map domain errors through module-specific mapRouteError utilities and add tests.
Frontend client
Expose a typed service function and React Query hook; update MSW handlers for stories/tests.

Add a new integration

Config
Add env schema in config/schema.ts or a feature config file. Document local and deployment variables.
Adapter
Place low-level client code in apps/backend/src/app/services or an owning module. Keep provider details out of shared.
Domain module
Integrate adapter calls through service logic, with typed errors and observable logs/metrics.
Local story
Add Docker/mock/test configuration if developers need the provider locally.
